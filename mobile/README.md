# CONDUCTOR mobile

Внутреннее мобильное приложение для работы с продажами CONDUCTOR.KZ. Оно живёт отдельно от публичной витрины сайта и доступно по адресу `https://conductor.kz/mobile/`.

## Что уже реализовано

- вход сотрудников через Firebase Authentication (Email/Password);
- рабочий дашборд: продажи за сегодня, новые и активные заказы, низкие остатки;
- быстрый заказ клиента;
- каталог DM30, DM60, DM90 и красок Холи;
- автоматический расчёт суммы;
- создание заказа и списание товара одной Firestore-транзакцией;
- статусы заказа: новый → подтверждён → отправлен → готово, а также отмена;
- склад с быстрыми корректировками остатков;
- заявки с публичного сайта: имя, телефон и выбранный товар;
- работа с заявкой в мобильном приложении: позвонить → в работу → закрыть;
- realtime-обновление между устройствами;
- постоянный локальный Firestore-кэш (IndexedDB);
- PWA: можно установить на главный экран Android как отдельное приложение.

## Первое подключение Firebase

1. В Firebase Console откройте **Project settings → Your apps**.
2. Если Web App ещё не создан, создайте его для `conductor.kz`.
3. Скопируйте объект `firebaseConfig`.
4. Для тестирования только на одном устройстве его можно вставить при первом открытии `/mobile/`; конфигурация сохранится в localStorage.
5. Для работы публичной формы заказа конфигурацию нужно записать в `mobile/firebase-config.js`. Firebase Web Config не является секретом и предназначен для клиентского приложения.

Никогда не помещайте в клиентский код service-account JSON, private keys или admin credentials.

## Authentication

В Firebase Console включите **Authentication → Sign-in method → Email/Password**.

В **Authentication → Settings → Authorized domains** добавьте `conductor.kz`, если домена там ещё нет. Без этого Firebase Authentication может отклонять вход с рабочего приложения на пользовательском домене.

Публичной регистрации в приложении нет. Учётные записи сотрудников создаются администратором проекта Firebase.

## Firestore

Создайте Cloud Firestore и опубликуйте правила из корневого файла `firestore.rules`.

Используются коллекции:

- `products` — товары, цены и остатки;
- `orders` — подтверждённые продажи и их статусы;
- `leads` — заявки посетителей публичного сайта.

Публичный посетитель не может читать Firestore. Правила разрешают ему только создать новую заявку `leads` с ограниченным набором проверяемых полей. Читать и менять заявки могут только авторизованные сотрудники.

Начальные товары:

| Код | Товар | Цена |
| --- | --- | ---: |
| DM30 | Цветной дым DM30 | 2 500 ₸ |
| DM60 | Цветной дым DM60 | 3 000 ₸ |
| DM90 | Цветной дым DM90 | 3 500 ₸ |
| HOLI | Краска Холи | 1 000 ₸ |

Начальный остаток каждого товара равен `0`: фактическое количество нужно внести на экране **Склад**.

## Сайт → мобильное приложение

На главной странице и на отдельных страницах товаров кнопки заказа подключены к общей модальной форме. Клиент видит выбранный товар и вводит только имя и телефон. После отправки создаётся документ в `leads`, и он в реальном времени появляется в блоке **Заявки с сайта** мобильного приложения.

Пока `mobile/firebase-config.js` пуст, существующие WhatsApp-ссылки остаются рабочим fallback и модальная форма не перехватывает кнопки.

## Установка на Android

Откройте `https://conductor.kz/mobile/` в Chrome и выберите **Установить приложение** / **Добавить на главный экран**. Приложение запускается отдельно от браузера в портретном режиме.
