# CONDUCTOR mobile

Внутреннее мобильное приложение для работы с продажами CONDUCTOR.KZ. Оно живёт отдельно от публичной витрины сайта и доступно по адресу `https://conductor.kz/mobile/`.

## Что уже реализовано

- вход сотрудников через Firebase Authentication (Email/Password);
- рабочий дашборд: продажи за сегодня, новые и активные заказы, низкие остатки;
- быстрый заказ клиента;
- каталог DM30, DM60, DM90 и красок Холи;
- автоматический расчёт суммы;
- создание заказа и списание товара одной Firestore-транзакцией;
- отмена заказа с автоматическим возвратом товара на склад;
- статусы заказа: новый → подтверждён → отправлен → готово;
- заявки с публичного сайта: имя, телефон и выбранный товар;
- конвертация заявки в заказ с автоматическим заполнением клиента и товара;
- клиентская база, объединяющая заявки и покупки по номеру телефона;
- история обращений и заказов клиента;
- полноценный складской учёт: поступление, списание, корректировка;
- последняя и средневзвешенная закупочная цена;
- оценка складского остатка по себестоимости;
- журнал движения товара с пользователем, временем, причиной и остатком до/после;
- продажи и отмены заказов автоматически попадают в журнал склада;
- realtime-обновление между устройствами;
- постоянный локальный Firestore-кэш (IndexedDB);
- PWA: можно установить на главный экран Android как отдельное приложение.

## Firebase

Firebase Web Config находится в `mobile/firebase-config.js`. Это публичная клиентская конфигурация, а не серверный секрет. Никогда не помещайте в клиентский код service-account JSON, private keys или admin credentials.

В Firebase Authentication используется Email/Password. Домен `conductor.kz` должен находиться в **Authentication → Settings → Authorized domains**.

## Firestore

Правила хранятся в корневом файле `firestore.rules`. После изменений правил их нужно опубликовать в Firebase Console или Firebase CLI.

Используются коллекции:

- `products` — товары, цены, остатки и закупочная стоимость;
- `orders` — продажи и их статусы;
- `leads` — заявки посетителей публичного сайта;
- `stockMovements` — неизменяемый журнал движения склада.

Публичный посетитель сайта может только создать строго валидированную заявку `leads`. Читать Firestore он не может. Склад, заказы, клиенты и журнал доступны только авторизованным сотрудникам.

Журнал `stockMovements` разрешено только читать и создавать. Изменение и удаление уже созданной складской операции запрещено правилами Firestore, чтобы сохранялась история учёта.

## Сайт → мобильное приложение

На главной странице и товарных страницах кнопки заказа открывают модальную форму. Клиент видит выбранный товар и вводит имя и телефон. После отправки заявка появляется в мобильном приложении в реальном времени.

Менеджер может позвонить клиенту, перевести заявку в работу или нажать **Оформить заказ**. При оформлении товара со склада списывается нужное количество и одновременно создаётся запись в журнале движения.

## Складской учёт

Для каждого товара доступны:

- **Поступление** — увеличивает остаток, сохраняет закупочную цену и пересчитывает средневзвешенную себестоимость;
- **Списание** — уменьшает остаток с обязательной фиксацией операции;
- **Корректировка** — задаёт фактический остаток после инвентаризации;
- **История** — показывает все операции по выбранному товару;
- **Журнал движения** — общая история склада.

При отмене заказа количество автоматически возвращается на склад и тоже фиксируется в журнале.

## Установка на Android

Откройте `https://conductor.kz/mobile/` в Chrome и выберите **Установить приложение** / **Добавить на главный экран**. Приложение запускается отдельно от браузера в портретном режиме.
