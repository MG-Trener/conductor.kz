# CONDUCTOR — склад и продажи

Внутреннее мобильное PWA-приложение CONDUCTOR.KZ доступно по адресу `https://conductor.kz/mobile/`.

## Назначение

Приложение используется только для внутреннего складского учёта и фиксации продаж. Функционал заявок с публичного сайта и клиентская CRM удалены.

## Основные возможности

- вход сотрудников через Firebase Authentication Email/Password;
- актуальные остатки DM30, DM60, DM90 и красок Холи;
- установка фактического остатка по каждому товару;
- поступление товара;
- ручное списание;
- автоматическое списание при продаже;
- отмена продажи с автоматическим возвратом товара;
- журнал всех движений склада;
- остаток до и после каждой операции;
- фиксация сотрудника и времени операции;
- оценка потенциальной стоимости склада по текущим ценам продажи;
- realtime-синхронизация между устройствами;
- локальный Firestore-кэш;
- установка на Android как PWA.

## Коллекции Firestore

- `catalog` — единая текущая цена продажи каждой модели;
- `products` — цветовые варианты и их остатки;
- `orders` — записи продаж;
- `stockMovements` — неизменяемый журнал движений склада.

Коллекция `leads` больше приложением не используется и закрыта правилами Firestore.

## Первичная настройка остатков

Откройте раздел **Склад**. У каждой модели нажмите **Цвета и актуальные остатки**, укажите единую цену модели и фактическое количество каждого цвета.

## Продажа

Откройте **Продажа**, укажите количество проданных товаров и при необходимости комментарий. Имя, телефон и другие персональные данные клиента не требуются. После сохранения:

1. создаётся запись продажи;
2. товар списывается со склада;
3. по каждой позиции создаётся запись в `stockMovements`.

При отмене продажи товар возвращается на склад отдельной обратной операцией.

## Безопасность

Публичный сайт не записывает клиентские данные в Firebase. Доступ к складу, продажам и журналу имеют только авторизованные сотрудники.

Актуальные правила находятся в корневом файле `firestore.rules`. Они разрешают складские операции только двум утверждённым email-аккаунтам, проверяют поля аудита и согласованность записи движения с итоговым остатком. Остальные коллекции закрыты по умолчанию.

Перед публикацией правил запустите локальные проверки:

```sh
npm install
npm test
```

После успешных тестов опубликуйте только правила Firestore:

```sh
firebase deploy --only firestore:rules
```
